# Audit, October 2026

An audit of every part of the tool for function and ease of use, done on 19 October 2026 against
commit `90048f0` and dataset 1.1.0. It follows the efficacy audit of 3 October (DECISIONS 50) and
goes wider: the plugin and both command line tools, the browser extension, the website and
calculator, and the engine and dataset underneath them.

Each idea is judged against four kinds of reader:

- **D**, developers in Claude Code or Codex, in long agentic sessions
- **E**, everyday chat users on claude.ai, ChatGPT or Gemini
- **O**, organisations and educators who want a group's footprint
- **R**, researchers and journalists who quote the figures

Impact and effort are rough: H, M or L for impact, S, M or L for effort.

## How it was done

The whole workspace was built and tested first: 30 turbo tasks, all green, parity 33 of 33, Python
82 of 82. Then:

- The command line tools ran against the owner's real Claude Code transcripts (4.9 GB, 453 files)
  and event log. Only counts and figures from that run appear here. No prompt text, session id or
  project name does.
- The built extension was loaded in Chromium 1243 and pointed at claude.ai, chatgpt.com and
  gemini.google.com while signed out. No prompt was sent and no account was touched. Turns were
  seeded through the extension's own `turn:captured` message to look at the popup and dashboard.
- The built site was driven in Playwright at 1440 and 390 pixels wide in both themes, behind its
  real content security policy.
- The engine was probed with small scripts against `packages/core/dist`, and its sources were
  checked where a constant looked wrong.
- Comparable tools were looked at for ideas worth borrowing. No code was copied.

Nothing in the repo was changed by the audit apart from this file. The `shots` scripts were not run,
because they overwrite tracked screenshots.

## What to fix first

Ranked by how wrong the figure or the experience is, and how many people see it.

1. **Thinking is counted twice, in two different ways.** The Claude Code reader adds thinking on top
   of an output count that already holds it (P1), and the engine adds a thinking estimate on top of
   benchmark rows that already include reasoning (E1). Together they inflate every reasoning
   model's figure, by 6% on the owner's fortnight and by 3.3 times for o3 on a short prompt.
2. **PUE is applied twice on all nine Jegham rows** (E2). Every OpenAI model except gpt-5, and every
   Claude model through the proxies, reads 12 to 14% high.
3. **The calculator's month and year totals are 30.4 and 365 times too high** for what the label
   says (S1).
4. **A missing water figure renders as zero** on the calculator (S2), which breaks hard rule 3.
5. **The browser hint never appears on a real site** (X1), stored turns overwrite each other (X2),
   and settings are wiped when the worker restarts before the first turn (X3).
6. **The Claude Code nudge cannot know the model** (P2), the mute command writes a file nothing reads
   (P3), and `/betteruseofai:report` can report the wrong session (P4).
7. **The recommender suggests "downgrades" that cost more** (E3) and fires on ordinary agentic
   instructions (E13).
8. **The command line tools take 50 seconds to two minutes** on a real machine (P5), and the Python
   one crashes when its output is piped on Windows (P6).
9. **The water scope setting does almost nothing** (S3): "lifecycle" equals the default for every
   model, and rows that publish water directly ignore the setting.

## Bugs

Each has the evidence and a severity. Where a subagent of the audit found it, the claim was checked
against the code before it went in. The ones marked "likely" could not be confirmed without a signed
in account.

### Plugin and command line tools

- **P1. Thinking counted twice on Claude Code. High.** `packages/readers/src/claude-code.ts:94`
  passes `output_tokens` unchanged and passes `output_tokens_details.thinking_tokens` beside it.
  Anthropic's `output_tokens` already includes thinking: across real turns the visible text tracks
  `output - thinking`, at the same ratio as turns with no thinking at all. `estimate.ts:148` then
  adds the two. When the details are null, the engine adds a thinking ratio on top of a count that
  already holds the thinking. Over 10,553 turns in the owner's fortnight, energy came out 129.4 kWh
  against 121.8 kWh corrected, a 6.2% overstatement. The Codex reader does this correctly
  (`codex.ts:89`). Fix: subtract reported thinking from output in the reader, and treat a null split
  as "included", with no lower bound flag.
- **P2. The nudge hook never receives a model. High.** `apps/cli-ts/src/commands/statusline.ts:322`
  reads `input.model?.id`. Claude Code's hook documentation says `UserPromptSubmit` carries no model
  field, only `SessionStart` sometimes does, and there is no model environment variable. So the
  recommender always runs with no model. It cannot name a target or a saving, and it would suggest a
  smaller model to someone already on Haiku. The tests pass because the fixture payload includes a
  model the real one lacks. Fix: read the model from the last assistant line of `transcript_path`,
  or keep the `to_model` of the last `PostModelSwitch` in the plugin's data folder.
- **P3. Muting does nothing. High.** `/betteruseofai:mute` writes a `muted` array to
  `~/.claude/betteruseofai/config.json`. No code reads that file; the hook's mute list is hardcoded
  at `statusline.ts:317`. The command also tells people to run `betteruseofai recommend`, which is
  not on the path for someone who only installed the plugin.
- **P4. The session report can show another session. Medium.** `commands/report.md` runs
  `session "$CLAUDE_SESSION_ID"`. That variable was empty in the Bash tool during the audit, so the
  command falls back to the most recent session, which is a different one whenever two sessions or a
  subagent run at once. Claude Code documents `${CLAUDE_SESSION_ID}` as a text substitution in
  command files, braces included, which is the reliable form.
- **P5. Slow on a real machine. High for D.** On 4.9 GB of transcripts: `summary --since 7d` took 51
  seconds, `sessions --since 2d` 49, `session <id>` 60, and `dashboard` two minutes. The reader parses
  every file and filters by date afterwards (`claude-code.ts:150` and `:178`). Only 196 MB had
  changed inside the seven day window. Python took 21 seconds for the same summary.
- **P6. The Python tool crashes when piped on Windows. Medium.** `cli.py:1777` writes `≥` to a cp1252
  stdout and raises `UnicodeEncodeError`. It works in an interactive console and fails in a pipe, a
  redirect or a scheduled task. Fix: reconfigure stdout to UTF-8, or fall back to `--ascii` when the
  encoding cannot carry the characters.
- **P7. The session report says its caveats twice. Low.** The flag notes print under the tables and
  again under "WHY THE FIGURES ARE UNCERTAIN", in different words.
- **P8. Dashboard charts hide the newest days. Low.** Both bar charts scroll sideways from the left
  (`packages/tokens/dashboard/template.html:950`), so the most recent bars start off screen even at
  1440 pixels, with no cue. "Put another way" gives energy and water and leaves carbon out.

### Browser extension

- **X1. The composer hint never mounts. High, confirmed live.** `packages/ui-hint/src/index.ts:251`
  guards with `typeof customElements === 'undefined'`. In a Chrome content script `customElements`
  is `null`, so `.get` throws, and `sites.content.ts:150` swallows the error. On Gemini a prompt the
  recommender scores at 0.70 produced no hint. The end to end test runs the hint in the page's own
  world, where custom elements exist, so it cannot catch this.
- **X2. Turns overwrite each other. High, confirmed.** The event id is adapter, conversation and
  `turnIndex` (`lib/pipeline.ts:72`), `turnIndex` restarts at 0 on every page load
  (`sites.content.ts:41`), and storage uses `put`. Gemini reads the conversation id from an API URL
  that never has one, so every Gemini turn is `no-conversation:N`. Send, reload, send again, and the
  popup still shows one turn.
- **X3. Settings are wiped on worker restart. High, reproduced.** `background.ts:273` resets settings
  to the defaults on every worker start while no turns are stored. Someone who answers the region
  question and changes settings before their first chat loses all of it. "Delete everything" also
  resets settings.
- **X4. ChatGPT's answering model is probably never read. High, likely.** `chatgpt.ts:88` looks for
  `metadata` where the older stream format kept it. The newer delta format wraps the first message
  as `{"p":"","o":"add","v":{"message":…}}` and puts text inside patch arrays. A probe in that shape
  gave no model and lost the last chunk, so every ChatGPT turn would read "unknown". The fixtures are
  hand written in the older shape.
- **X5. Gemini's model almost never resolves. High, partly confirmed.** The XHR wrapper sends empty
  request headers (`interceptor.ts:168`). The header's "longest string" rule (`gemini.ts:63`) picks
  an opaque id. The picker live reads "Flash-Lite" and the page says "Gemini 4", and the dataset has
  no Gemini 3 or 4 rows and no mapping for picker labels.
- **X6. Gemini token counts include the response wrapper. Medium, probe only.** `gemini.ts:113` takes
  the longest string in each chunk, which is the whole inner JSON: 469 characters counted for a 31
  character answer.
- **X7. claude.ai regenerations and attachments are missed. Medium, likely.** The `/retry_completion`
  path is not intercepted (`claude.ts:20`), and attachment text in `extracted_content` is not read
  (`claude.ts:41`). Images are ignored on all three sites with no flag.
- **X8. Placeholder usage counted as provider data. Medium.** `claude.ts:120` accepts the usage block
  of `message_start`, which can give an output of 1 marked as not estimated.
- **X9. Site health is wrong and forgotten. Medium.** It probes once, 1.5 seconds after load
  (`sites.content.ts:91`), keeps the result in worker memory (`background.ts:63`), and labels a
  signed out page "unsupported". The popup then says the site "has stopped counting", which the
  code does not actually do.
- **X10. ChatGPT composer selectors miss. Medium, confirmed signed out.** The composer is now
  `textarea#mobile-composer-prompt`, and `readDraft` uses `textContent`, which is always empty for a
  textarea (`chatgpt.ts:155`).
- **X11. Smaller ones.** The popup shows the first four models alphabetically rather than the most
  used (`popup/App.tsx:137`). Arrow keys in the first run region list pick a region on the first
  press (`popup/App.tsx:214`). Days are bucketed in UTC and empty days are dropped. An aborted
  stream throws in the page and drops the partial turn (`interceptor.ts:103`). The DOM fallback and
  local model support are described in copy but not wired up. Unknown models don't make the headline
  a lower bound (`Readout.tsx:50`). "Delete everything stored" has no confirmation.

### Website and calculator

- **S1. Month and year totals multiplied twice. High.** `Calculator.tsx:248` multiplies the prompt
  count by 30.4 or 365, while the label at `:321` reads "Prompts a month" and the copied text says
  "20 prompts a month". `#model=claude-opus-5&prompts=20&period=month` shows 3.08 kWh, which is 608
  prompts.
- **S2. Missing water renders as zero. High, breaks hard rule 3.** `estimate.ts:217` falls back with
  `row.waterOnsiteLPerKwh ?? ZERO`. `#model=deepseek-r1-distill-llama-70b&scope=on-site` shows
  `≥ 0 mL [ 0 to 0 ]`. The test at `tests/site.test.ts:280` can't catch it.
- **S3. The water scope setting mostly does nothing. High for R.** No row carries
  `embodiedShareOfTotal`, so "the whole life of the hardware" equals the default for all 34 models.
  Rows that publish water directly ignore the scope (`estimate.ts:211`): gpt-5 gives 1.08 mL under
  every scope and Mistral Large 2 shows its lifecycle figure under "on site only". The carbon uplift
  at `:247` is keyed to the water scope.
- **S4. Whole numbers lose their trailing zeros. High.** `index.astro:511` strips `0+$` from integers
  as well as decimals, so 1210 becomes 121. At 500 prompts carbon reads `≥ 116 g [ 123 to 14619 ]`,
  a central below its own low.
- **S5. Inputs accept nonsense. Medium.** Negative prompt counts give negative footprints and go into
  the hash (`Calculator.tsx:327`). Clearing a field snaps it to 1, so typing 50 gives 150. The hash
  clamps values the inputs allow (`:71`), so a shared link shows different figures. Values outside
  the option lists blank the dropdowns, and an unknown region says "No region was given".
- **S6. The local comparison hides its own flags. Medium.** The sources block reads only the cloud
  side (`Calculator.tsx:495`), so a local model priced from a data centre row says "heavier by
  roughly 3.33 times" with no warning.
- **S7. Copy as text misdescribes itself. Medium.** It says the token counts came from our
  tokenizer when they were typed by hand, runs to 244 characters a line, prints ids rather than names,
  and has no date, period or link back.
- **S8. The methodology table prints raw slugs. Medium.** `methodology.astro:31` maps method names
  the dataset doesn't use, so 16 of 24 rows show slugs, and rows show ids rather than titles.
- **S9. Smaller ones.** 89 pixels of sideways scroll on the landing page at 390, and 208 on
  methodology and changelog from an unbroken SHA-256. No live region on the calculator's results and
  no headings below the h1. With JavaScript off the calculator shows defaults and ignores the hash
  with no notice. The install page says `doctor` removes the cache, which it doesn't
  (`misc.ts:187`), leaves the event log out of the uninstall steps, and says Node 22 where `doctor`
  accepts 20. No `robots.txt`, no `og:image`.

### Engine and dataset

- **E1. Thinking added to rows that already include it. High.** `estimate.ts:70` adds
  `output × thinkingRatio` for any reasoning model with no reported count, without asking whether the
  row includes reasoning. `jegham.o3` says in its own note that "the thinking tokens are already
  inside these numbers"; o4-mini was measured at high effort, and the Altman and Google medians
  include reasoning too. o3 on 200 in and 300 out comes out at 5.45 Wh central where the row gives
  1.64. Fix: an `includesThinking` field on rows, and a handling of `included-in-row`.
- **E2. PUE applied twice on every Jegham row. Medium.** All nine `jegham.*` rows set
  `energyIncludesPue: false`, so `estimate.ts:179` multiplies by 1.12 to 1.14 again. The paper's
  Eq. 1 ends in `· PUE`, and its water equation applies on site WUE to `E / PUE`, which the engine
  doesn't do either.
- **E3. Downgrades that cost more. High.** `recommender/index.ts:158` never checks that the target is
  cheaper. "tidy this paragraph please" on o3 suggests o4-mini, which the engine prices higher, with
  a saving of `[0, 0, 3.73]` and `showAsHint: true`.
- **E4. Savings ranges treated as independent. Medium.** `saving.ts:60` and `recommender/index.ts:56`
  compute `before.low - after.high`, so the low is almost always 0, though both sides share the same
  rows. 100 Sonnet 5.5 turns give `[0, 322, 9360]` Wh; correlated, it's `[28.6, 322, 5240]`. The
  dashboard's rings always start at "possibly nothing".
- **E5. "≥ central" contradicts the bracket. Medium.** `format.ts:105` prints `≥ 4.99 Wh [ 0.550 to
  60.2 ]`. The central already includes an estimated thinking share, so it isn't a floor, and in
  Claude Code (P1) it is an overestimate. The status line unions flags, so `≥` sits on almost every
  Claude Code total.
- **E6. Single prompt rows divide every bound by the central token count. High for R.**
  `normalize.ts:226` divides a 4,000 token reasoning high by a 500 token reference, then widens it.
  A 200 and 300 token reply on the R1 distill comes out at 0.011 to 208 Wh, and Gemini 2.5 Pro at
  0.07 to 282 Wh. Those are figures someone could quote.
- **E7. Local Mistral priced from the cloud lifecycle row with no flag. Medium.** `estimate.ts:135`
  infers "hosted row on a local model" from `pue.high > 1`, and the Mistral lifecycle row has PUE 1.
  Fix: compare the row's hosting with the event's.
- **E8. Provider reported carbon falls back silently. Low.** Proxy rows have no `carbonGPerKwh`, so
  they use the grid figure while the basis says "provider-reported" (`estimate.ts:245`).
- **E9. Energy totals drop turns with no energy figure without a count. Medium.**
  `aggregate.ts:82` counts only unknown models and missing rows. A Le Chat turn has water and carbon
  but null energy, and disappears from the energy total with no `≥`.
- **E10. Wrong message for frontier models with no rung below. Low.** GPT-5.6 and Fable 5.1 are
  described as "already the smallest model we know on its ladder" (`recommender/index.ts:166`).
- **E11. The swap is priced on a fixed date and a toy shape. Medium.** `priceSwap` pins
  `at: '2026-09-10'` (`index.ts:225`), ignores the region, and prices a short agentic prompt at
  0.47 Wh against a real turn of about 16 Wh driven by cached context.
- **E12. Hourly grid ranges summed as if every turn hit the dirtiest hour. Medium.** 1,000 turns in
  Great Britain give a carbon high to low of 14.6 times, against 4.0 for energy.
- **E13. Recommender matching is loose. Medium.** `features.ts:253` matches imperatives with
  `startsWith`, so "listen" counts as "list". "extract the parser into its own module" and "correct
  the failing tests" fire downgrades at 0.7 to 0.8. Arithmetic fires at 0.95 on a date ("2026-10-19"
  gives "The answer is 1997") and on phone numbers, and no-llm answers skip vetoes.
- **E14. TypeScript and Python disagree outside the parity cases. Low.** "1.2.3 km to m" gives
  "1200 m" in TypeScript and nothing in Python; very large products format differently; word
  splitting and the non-Latin pattern differ; Python's `estimate` ignores `modelId`.
- **E15. Equivalent constants. Medium.** The kettle mug is 100 Wh where 300 mL from 10 °C needs about
  35 Wh with losses (`equivalents.json:50`), which makes AI look smaller than it is. The car figure,
  244 g/km, is cited to DESNZ but is the EPA's US figure. The phone charge's carbon embeds the US
  grid, so in France one estimate can be half a charge of energy and three hundredths of a charge of
  carbon. The metric teaspoon is 4.9 mL. A typical 0.3 Wh prompt finds nothing to compare with
  except a 2009 web search.
- **E16. Stale methodology text. Medium for R.** The `regions.json` note and the methodology skill
  (`SKILL.md:68`) still say every region shares one US water range. `SKILL.md:79` says cache writes
  usually dominate; on the owner's fortnight cache reads did, 2.2 billion tokens against 121 million
  written. `input-partial` fires on every Claude Code turn with "The app hides its system prompt",
  which isn't true there.

## The nudge in Claude Code

This was left open in DECISIONS 50. It was measured again on 240 real prompts across 27 sessions
from the last fortnight, with the model each session actually used:

| Bar | Prompts nudged | Rule |
|---|---|---|
| Plugin bar (0.75, three mutes) | 1 of 240 | `no-llm.date-math` |
| Default bar (0.6) | 66 of 240, 27% | 65 of them `downgrade.short-simple` |
| Default bar, first prompt of a session only | 10 of 27 | all `downgrade.short-simple` |
| Report threshold (0.45) | 105 of 240, in 26 of 27 sessions | mixed |

Reading the session openers the default bar would have nudged, every one was a short instruction
that launched a long task: carry on from a handoff note, continue a batch, check on a script, start
a server. A short prompt in an agent is a pointer to a lot of context, so prompt length tells us
nothing about the work. And because of P2, any nudge that did fire couldn't name a model.

Where the energy actually goes in a coding session is clear from the same fortnight:

- 61% of turns carried more than 150,000 tokens of context, and those turns hold 75% of the energy.
- Re-reading cached context accounts for 47% of the central figure. That share rests on
  `cachedReadShareOfInput`, an assumption from 0 to 0.5 with a central of 0.1, so it is the least
  certain number in the chain.
- The Opus turns, priced as Sonnet 5.5 instead, fall from 94.2 to 51.8 kWh.

So the levers in an agent are the size of the context and the choice of model for the session. The
wording of any single prompt matters much less.

The options:

1. **Keep it as it is.** It fires on about 0.4% of prompts and can't name a model. Honest, but in
   practice the feature is off.
2. **Drop to the default bar.** Over a quarter of prompts nudged, nearly all wrongly. This is the
   outcome the plugin's README warns gets the feature switched off.
3. **Nudge only the opening prompt.** Fewer interruptions, but on this data every one would have been
   wrong for the same reason.
4. **Move the nudge from the prompt to the session.** Turn off the per prompt hint in Claude Code.
   Use the Stop hook, which already runs, to say at most one thing a session, after the turn, when
   the measured facts justify it. Two triggers: the context passing a size (for example 150,000
   tokens), with a note that the cost of re-reading it is the least certain part of the estimate; and
   a long session on the top model, with what the same turns would have cost one rung down, priced
   from the real token counts.

**We'd pick option 4.** It's built on measured turns rather than guesses about intent, it can't
interrupt someone mid-thought, and it points at the two things that move the number. It needs P2
fixed to know the model, P3 fixed so people can mute it, and E4 fixed so the saving isn't always "0
to something". It would be wise to pair it with engine idea E-I3 below, so the context message rests
on a fitted cost rather than the 0.1 assumption. The extension's per prompt hint is a different case:
chat prompts are self-contained, so the prompt-level rules make sense there once X1 and E13 are
fixed.

## Ideas

### Plugin and command line tools

- **P-I1. Skip files that can't be in the window.** A transcript's modified time is at or after its
  last event, so files older than `--since` can be skipped before parsing, and `session <id>` only
  needs `<id>.jsonl` and its subagent files. Pre-filter lines on `"type":"assistant"` before parsing
  JSON. Evidence P5. H, S, D. Touches `packages/readers/src/claude-code.ts`, `jsonl.ts` and the
  Python reader.
- **P-I2. Context hygiene in the session report.** Add a column for context size per turn, the share
  of the session's energy above 150,000 tokens, and when it crossed. Evidence: the nudge section. H,
  S, D. Touches `commands/sessions.ts` and the dashboard template.
- **P-I3. Model from the transcript, mutes from the data folder.** Fixes P2 and P3 in one move: read
  the model from the transcript tail and keep `config.json` under `CLAUDE_PLUGIN_DATA`, which
  survives plugin updates. H, S, D. Touches `statusline.ts` and `commands/mute.md`.
- **P-I4. `doctor` checks the status line.** The setup command writes an absolute path into the
  installed plugin's versioned folder (`cache/betteruseofai/betteruseofai/0.0.0/dist`). After a
  version bump that path can vanish and the line goes blank without a word. Have `doctor` read the
  `statusLine` entry and say whether its file exists. M, S, D. Touches `misc.ts`.
- **P-I5. A "this week versus last week" line** in `summary` and the Stop hook's ten turn message, so
  a change in habit shows up as a number. M, S, D and O.
- **P-I6. Ranges on export.** `export` writes only the central figures. Researchers need the low, the
  high and the flags in each row. M, S, R. Touches `commands/export.ts` and the canonical schema.
- **P-I7. Five hour block view.** People already think in Claude Code's five hour usage windows,
  which is why ccusage's block report is popular. A `--by block` bucket would line our figures up
  with the window they watch. M, S, D. Touches `aggregate.ts`.
- **P-I8. Status line refresh.** Claude Code's `refreshInterval` setting reruns the status line on a
  timer. Setup could offer it so the line doesn't freeze while the session is idle. L, S, D.

### Browser extension

- **X-I1. Mount the hint without custom elements**, with a plain host element and a shadow root, and
  an end to end test that runs the real content script on a routed fake chat page. Fixes X1. H, S, E.
- **X-I2. Stable turn ids** from the stream's message id, conversation id from `location.href`, and a
  storage migration. Fixes X2. H, S, all.
- **X-I3. A diagnostics page** listing the last 20 captures: site, raw model string, where the model
  came from, token counts, flags, adapter version and health, never any text. It turns the owner's
  hand check from DECISIONS 50 into a five minute job and lets users file useful bug reports. H, S, D
  and R. A new `entrypoints/diagnostics/` and an `events:recent` handler.
- **X-I4. Recorded, scrubbed fixtures** of the current ChatGPT delta stream, Gemini over XHR with the
  real header, and claude.ai retries and attachments. Fixes the blind spot behind X4 to X8. H, M, D.
- **X-I5. Picker labels per site and Gemini 3 and 4 rows**, mapped exactly ("Flash-Lite", "Fast",

### Engine and dataset

- **E-I1. Sensitivity on every estimate.** Recompute the central with each assumption at its low and
  high and return the list, sorted. On one Opus Claude Code turn the cache read share swings it 13
  times, the Opus proxy factor 4.5 and Jegham's uncertainty 4. Then the session report and popup can
  say which unknown the range mostly comes from. H, M, D, O and R. Touches `estimate.ts` and
  `estimate.py`.
- **E-I2. Combine independent factors in log space.** Today's low and high are the joint extremes of
  four or more factors at once, far beyond any one factor's own spread. Tag which inputs are shared
  and which independent, and combine the independent ones in quadrature, with a floor so a low of 0
  doesn't break it. H, M, R and O. Touches `range.ts`, with a parity fixture.
- **E-I3. Model the cost of long context.** Epoch's GPT-4o shape gives about twice the energy per
  output token at 10,000 to 100,000 tokens of context. Fit that, charge output against context size,
  and retire most of the weight on `cachedReadShareOfInput`. H, L, D. Touches `normalize.ts` and
  `estimate.ts`.
- **E-I4. `includesThinking` and `directScope` on rows**, enforced by the schema. Fixes E1 and S3
  structurally. H, S, all.
- **E-I5. A recommender that knows it is in an agent.** A veto for short prompts deep in a
  `claude-code` or `codex-cli` session, word boundaries on the imperatives and reasoning cues, no
  arithmetic on dates or phone numbers, a "target is cheaper" check, and `priceSwap` fed the real
  context size and region. M, M, D. Touches `features.ts`, `rules.ts`, `index.ts` and the Python
  mirrors, with the audit's prompt set added to parity.
- **E-I6. Energy from the next row when the chosen row has none**, flagged, and a count of turns
  without energy in aggregates. Fixes E9. M, S, E and R.
- **E-I7. Better equivalents.** Correct the kettle and the car, add a 0.01 to 1 Wh comparison such as
  minutes of a 9 W LED, use household days by region (UK 7.4 kWh, US about 29), and work out the
  carbon phone charge from the region's grid. M, S, E and O.
- **E-I8. Dataset upkeep.** An exact alias rule for date suffixes and `[1m]` in `resolve.ts` and
  `engine.py`, a test that each family has one current smallest model and that every proxy's parent
  exists, and `priceSwap` defaulting to today. M, S, D and R.
- **E-I9. Annual grid spread for long buckets.** Use the hourly spread for one turn and the annual
  spread for a week. Fixes E12. M, S, O and R.
- **E-I10. Use or delete the parametric server overhead.** `serverBaseW` and `gpuCount` sit in the
  schema and the data, and `normalize.ts` never reads them. M, S, D and R.
- **E-I11. Embodied impact, or say plainly it's missing.** EcoLogits adds the share of the hardware's
  manufacture to each request. Either add it as the lifecycle scope's content, which would give S3 a
  real figure, or label that scope as not yet available. M, M, R.

### A wider question for the owner

People who use Claude Code heavily already watch money and quota, which is why cost tools are popular.
Prices could ship in the dataset like everything else, with no network, and "Sonnet would save X Wh
and $Y" is likely to move more people than watt hours alone. It changes what the project is about, so
it's listed here for a decision rather than as an idea in the lists above.

## Ideas that need a hard rule relaxed

Kept apart so they can be accepted or turned down one by one.

- **Remote adapter fixes.** Selectors and endpoint patterns fetched from the website, so a broken site
  adapter can be fixed without a store release. Breaks "no remote fetches".
- **Opt-in breakage reports** from the extension, so the owner doesn't have to check sites by hand.
  Breaks zero telemetry.
- **Organisation totals** pooled across staff browsers or machines. Needs a backend.
- **Sync across devices** through `chrome.storage.sync`, which sends data to the browser vendor.
  Breaks strictly local.
- **Live grid intensity** for the hour and region of inference, from NESO or the EIA. Needs network
  fetches; Electricity Maps is ODbL and stays out either way.
- **Link previews of a calculator state.** The state would have to move into the query string.
- **Tokenizer calibration** against the providers' counting endpoints. Needs network calls and API
  keys.
- **Wall meter readings** sent in by volunteers, to calibrate the local row (the local figure barely
  changes between 3B and 70B parameters today). Telemetry.

## What was not checked

- Signed in pages on claude.ai and ChatGPT, and therefore any real request or stream body.
- Firefox.
- Codex, since this machine has no Codex rollouts, and Gemini CLI.
- The release and snapshot workflows.
- Whether `PostModelSwitch`, which Claude Code does document, fires on every switch path the plugin
  cares about.
